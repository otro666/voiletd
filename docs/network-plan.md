# Связь по сети на T-Deck — чего нет и что нужно

Короткий ответ на вопрос: **не сделано ничего**. Ни DHT, ни рельс, ни определения внешнего
адреса. В коде есть только выбор между «Wi-Fi» и «радио» и подсчёт того, что по какому
пути можно отправить, — но самой отправки по сети нет ни строчки.

Wi-Fi на плате сейчас умеет ровно одно: подключиться к точке доступа. Дальше — тишина.

---

## Что вообще нужно, чтобы связь по сети заработала

Разложу по слоям, от простого к сложному. Порядок важен: каждый следующий имеет смысл
только поверх предыдущего.

### 1. Локальная сеть — самое простое и самое ценное

Телефонная версия рассылает по локальной сети объявление о себе: групповой адрес
`239.255.77.77`, порт `47771`, раз в пять секунд. Кто в той же сети — находит.

**Это надо делать первым.** Причины:

- реализуется за вечер: обычный сокет и таймер;
- работает **без интернета вообще** — телефон и плата в одной домашней сети находят друг
  друга напрямую;
- не нужно ни внешних адресов, ни посредников, ни пробивания преград;
- сразу даёт связь с телефоном, а это главное, ради чего плата подключается к сети.

Формат объявления уже определён в телефонной версии — надо просто повторить.

### 2. Прямой обмен по UDP

Собеседник найден — дальше идёт обычный обмен пакетами. Формат провода уже написан и
проверен: рукопожатие, храповик, шифрование. Остаётся сокет и подача в него.

Тут работы немного: весь протокол готов, нужен транспорт под ним.

### 3. Определение внешнего адреса

Нужно, только когда собеседники в РАЗНЫХ сетях. Плата спрашивает у публичного сервера,
как её видно снаружи, и сообщает адрес собеседнику.

Реализуется просто — короткий запрос по UDP и разбор ответа. Список серверов уже подобран
в телефонной версии.

### 4. Пробивание преград

Оба собеседника одновременно шлют пакеты навстречу, и домашние маршрутизаторы открывают
проход. Работает не всегда: при некоторых видах подключения у оператора прохода нет в
принципе.

### 5. Рельсы знакомства — MQTT и Nostr

Способ найти собеседника, когда он в другой сети и адрес заранее неизвестен. Обе стороны
приходят в общую «комнату», выведенную из кодового слова, и обмениваются адресами.

Готовые библиотеки для платы есть, но Nostr требует подписи на другой кривой — это
заметная работа.

### 6. DHT

Самая тяжёлая часть: распределённая таблица без единого сервера. Требует таблицы узлов,
опроса соседей, устойчивости к обрывам и аккуратности с памятью — её на плате мало.

**И вот что важно:** для связи с телефоном она **не нужна**. Нужна для полной
самостоятельности — чтобы плата находила собеседников без единого посредника.

---

## Что я предлагаю по порядку

| шаг | что даёт | сложность |
|---|---|---|
| локальная сеть | связь с телефоном в одной сети | вечер |
| обмен по UDP | переписка, файлы, голосовые | день |
| внешний адрес | связь между разными сетями | день |
| пробивание преград | то же, когда прямого пути нет | пара дней |
| MQTT | знакомство через интернет | пара дней |
| Nostr | второй путь знакомства | неделя |
| DHT | полная самостоятельность | недели |

**Первые два шага дают восемьдесят процентов пользы.** Плата в домашней сети переписывается
с телефоном, шлёт файлы и голосовые, а в поле переключается на радио. Остальное —
для случая «собеседник в другом городе, интернет есть у обоих».

---

## Чего я НЕ стану обещать

Слои с четвёртого по шестой я не смогу довести вслепую. Пробивание преград и DHT
проверяются только в живой сети, у разных операторов, с разными маршрутизаторами — а у
меня нет ни платы, ни возможности что-либо измерить. Написать их можно, но отлаживать
придётся тебе, и это займёт заметно больше, чем написание.

Первые три слоя другого свойства: они либо работают, либо нет, и это видно сразу.
