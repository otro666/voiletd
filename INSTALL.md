# Установка на T-Deck

## Самый простой способ — через браузер

Ничего устанавливать не нужно: ни PlatformIO, ни компилятора, ни драйверов.

1. Залейте проект в репозиторий на GitHub.
2. Во вкладке **Settings → Pages** выберите источник **GitHub Actions**.
3. Пушните в ветку `main`. Сборка соберёт прошивку сама и опубликует страницу заливки.
4. Откройте её адрес **в Chrome или Edge**, подключите плату кабелем, нажмите
   «Прошить устройство».

Готовый файл прошивки лежит и во вкладке **Actions** — в артефактах каждой сборки,
если захочется залить его иначе.

Работает это через WebSerial — встроенную возможность Chrome общаться с портом прямо со
страницы. В Firefox и Safari её нет вовсе, и обойти это со стороны страницы нельзя.

## Через командную строку

## Коротко

```bash
pip install platformio
cd vual-deck
make test              # 133 проверки, до всякого железа
pio run -t upload
pio device monitor
```

Ниже — то же самое, но с местами, где обычно спотыкаются.

---

## 1. Что нужно

- кабель USB-C **с передачей данных**, а не только зарядный. Половина случаев «плата не
  определяется» — именно кабель;
- Python 3;
- плата с **подключённой антенной 433 МГц**;
- microSD в формате FAT32 — без неё переписка не переживёт выключение.

**Антенна должна стоять до подачи питания.** Передача без неё отражает мощность обратно в
усилитель — это единственное, что убивает модуль SX1262 необратимо.

## 2. Поставить PlatformIO

```bash
pip install platformio
```

Или расширение PlatformIO IDE для VS Code — тогда всё делается кнопками.

## 3. Проверить логику до заливки

```bash
cd vual-deck
make test
```

133 проверки: формат кадра, разнесение копий, храповик, сжатие звука, выбор транспорта,
журнал на карте, работа с картинками, жесты, кириллическая раскладка и совместимость
знакомства с телефоном. Всё это не зависит от железа.

Если здесь что-то падает — на плате разбираться будет несравнимо труднее.

## 4. Сверить распиновку — ОБЯЗАТЕЛЬНО

Откройте `include/board.h` и сверьте с официальным репозиторием LilyGo:

```
github.com/Xinyuan-LilyGO/T-Deck  →  examples/UnitTest/utilities.h
```

Значения выписаны по документации, но LilyGo меняла разводку между ревизиями. Ошибка в
одном выводе даёт чёрный экран или молчащее радио, и ищется вслепую долго.

Если правите — правьте **и `board.h`, и флаги `TFT_*` в `platformio.ini`**: библиотека
экрана настраивается на этапе компиляции, а не в коде, и про `board.h` она ничего не знает.
Это самая частая причина «прошилось, но экран чёрный».

## 5. Проверить TCXO

В `board.h` стоит полоса 31,25 кГц — она даёт +6 дБ к чувствительности, но требует
термокомпенсированного генератора: допуск ±18 ppm, обычный кварц при нагреве за него
уходит, и связь пропадает именно тогда, когда усилитель прогрелся.

Если TCXO нет:

```c
#define LORA_BW_KHZ   62.5f    // вместо 31.25
#define LORA_TCXO_V   0.0f     // генератор не используется
```

Потеряете половину выигрыша, зато связь будет устойчивой.

## 6. Задать фразу знакомства

Экрана знакомства пока нет, поэтому фраза задаётся в коде. Найдите в `src/main.cpp`:

```cpp
static const char kPhrase[] = "зелёный чайник";
```

**Поменяйте на свою** и залейте одну и ту же фразу на обе платы. Из неё выводится общий
секрет — платы найдут друг друга сами. Эта фраза известна всем, кто читал исходники.

## 7. Собрать и залить

```bash
pio run -t upload
```

Первая сборка займёт несколько минут: скачиваются набор инструментов и библиотеки.

Плата не определилась — переведите её в режим загрузки: удерживая **BOOT**, нажмите и
отпустите **RST**, затем отпустите BOOT.

На Linux может не хватать прав на порт:

```bash
sudo usermod -a -G dialout $USER    # затем перезайти в систему
```

## 8. Посмотреть, что происходит

```bash
pio device monitor
```

При успешном запуске в порт выводится:

```
сенсор GT911 на адресе 0x5D
фраза знакомства: «...»
адрес встречи в эфире: XXXXXXXX
Вуаль готова
```

Если вместо этого «радио не поднялось» с кодом — почти всегда либо распиновка, либо
отсутствие TCXO при узкой полосе. Если «сенсор не найден» — управление останется на
клавиатуре и трекболе, это не смертельно.

## 9. Управление

| действие | как |
|---|---|
| выбрать собеседника | касание строки или трекбол вверх-вниз |
| открыть переписку | касание, нажатие трекбола или Enter |
| вернуться назад | смахнуть справа налево |
| прокрутить | смахнуть вверх или вниз |
| **переключить раскладку** | **касание значка «РУ» / «EN»** или клавиша `$` |
| отправить | Enter |

Значок раскладки всегда на виду слева в строке ввода — иначе непонятно, почему нажимаешь
Q, а получается Й.

Повесить переключение на Alt невозможно: клавиатура висит на отдельном микроконтроллере
и отдаёт уже готовый символ, а нажатые в одиночку Alt и Shift не возвращают ничего.

Если `$` не подходит для вашей прошивки клавиатуры — в `src/hw_input.cpp` включите
`kDumpCodes`, нажмите желаемую клавишу, посмотрите код в мониторе и впишите в
`kLayoutKey`.

## 10. Испытания

Нужны **две платы**. Менять по одному параметру за раз, иначе непонятно, что дало результат:

1. рядом на столе — убедиться, что текст ходит;
2. 100 метров с прямой видимостью — записать RSSI и SNR;
3. увести одну за здание — настоящая проверка;
4. поднять одну повыше и сравнить. Разница будет самой большой из всех, что вы увидите.

---

## Чего пока нет

- **обмен по UDP с телефонами** — модуль транспорта написан и протестирован, но сам обмен
  не подключён. Совместимость знакомства с телефоном проверена эталонными значениями;
- **экран знакомства** — фраза задаётся в коде;
- **рация** — удержание распознаётся, передача звука не подключена;
- **ретрансляция** через промежуточные узлы.

Радиочасть, шифрование с храповиком, разнесение копий против городских переотражений,
хранилище на карте, ввод и интерфейс — готовы.
